# Case 071 - 已停售商品退廚後預估可賣數量錯誤

## 自主測試內容

POS 版次：v4.X.X

結帳方式：此問題不分前後結

訂單識別值：[ID]

線上訂單關聯編號：[ID]

自主測試發現，商品以快選數量點選多份後設為暫時停賣，再進行單項退廚，畫面上的預估可賣數量會錯誤顯示原始點餐數量，而不是本次退回的數量。退換貨流程也有相同問題。

## 查詢結果

### 掛單後單項退廚

- [DATE] [TIME]：開桌並以快選數量點選商品 5 份。
- 將該商品設定為暫時停賣。
- 操作掛單後再次開啟訂單。
- 對商品操作可退廚數量 1。
- 商品預估可賣數量顯示「剩：5」，正確應為「剩：1」。

### 結帳後退換貨

- 另開訂單，以快選數量點選另一商品 5 份。
- 將商品設定為暫時停賣並完成結帳。
- 操作退換貨，退回數量 1。
- 商品預估可賣數量同樣顯示「剩：5」，正確應為「剩：1」。

判斷已停售商品在退廚或退換貨回補預估可賣數量時，使用了原訂單商品數量，而非實際退回數量。

## 處理判定

系統問題，已上 Issue [ID]，請開發端修正停售商品於退廚及退換貨流程中的預估可賣數量回補基準。
