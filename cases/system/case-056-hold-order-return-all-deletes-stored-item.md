# Case 056 - 掛單後全部退廚誤刪會員寄存商品

## 自主測試內容

POS 版次：v4.X.X

結帳方式：此問題不分前後結

訂單識別值：[ID]

線上訂單關聯編號：[ID]

自主測試發現，同一訂單點選兩份商品並將其中一份設為會員寄存，掛單後操作全部退廚，寄存商品會一併被移除。

列印的退廚房單與退廚房總單數量呈現 -2，正確應只退廚非寄存商品 1 份，數量為 -1。

## 查詢結果

測試流程：

- [DATE] [TIME]：點選桌號並開桌。
- [DATE] [TIME]：點選相同商品 2 份，其中 1 份設定為會員寄存。
- [DATE] [TIME]：操作掛單。
- [DATE] [TIME]：操作全部退廚。

實際結果：

- 會員寄存商品與一般商品一併從訂單移除。
- 退廚房單與退廚房總單的退廚數量為 -2。

預期結果：

- 全部退廚只應處理可退廚的一般商品。
- 會員寄存商品應保留。
- 退廚單據數量應為 -1。

交叉測試：

- 先送廚但不掛單，直接操作全部退廚，寄存商品會保留。
- 先送廚、掛單後再操作全部退廚，寄存商品不會保留。
- 訂單中只有寄存商品時，無法點選全部退廚。

判斷掛單前後的全部退廚流程對寄存商品採用不同的篩選或狀態判斷，導致掛單後寄存商品被錯誤納入退廚與刪除範圍。

## 處理判定

系統問題，已上 Issue [ID]，請開發端修正掛單後全部退廚的商品篩選、寄存狀態保留與退廚單據數量計算邏輯。
